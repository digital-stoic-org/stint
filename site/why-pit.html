  • What does it mean?
Agent / session = the driver: a model working on your task, from first prompt to last. Lap = one agent turn, one call to the model. Context = everything the model re-reads on each lap; it grows lap after lap. Stint = a stretch of laps between two pit stops. Pit stop = reset the context to a short handoff, then keep racing. Handoff / seed = the notes that survive a pit: goal, decisions, next step. They seed the next stint. Cached input = context already sent, re-read at a lower rate. Effort = how much the model thinks and writes per lap; more effort, more output tokens.
Presets

Effort scales output tokens per lap: low 0.52 · medium 1.00 · high 1.38 · xhigh 3.52 · max 5.0 (placeholder). An approximation derived from the official cost-per-task benchmark, not an official token ratio. Effort docs

How this is computed
  1. A lap is one call. Its prompt is the whole context so far plus the new input of the lap (tool results, user turn).
  2. The reply is billed at the output price and appended to the context. Its size is the base output times the effort multiplier.
  3. Cached input on: the prompt already sent on the previous call is read at the cache-read price, and everything new since then (last reply and new input) is written at the 5-minute cache-write price. Cached input off: the whole prompt is billed at the base input price.
  4. Stints are deduced, not chosen. Before a lap, if the prompt would cross the pit threshold, the agent pits. A pit costs one extra call that reads the context and writes the handoff as output. The next stint starts from the handoff seed with a cold cache.
  5. Haiku 5.5 is tiered by prompt size: each call uses the rates for prompts up to 100k tokens or over 100k tokens.
  6. Not modelled: cache expiry between laps (laps are assumed to come within 5 minutes), system prompt and tool definitions, batch or regional pricing, and answer quality as the context grows.
